# Claude Code — Windows Research Directive
## Authority and priorities
Build the strongest practical **private Windows NBA research laboratory** you can. This project deliberately does **not** use the standard Mundy Morning Studios Android template. Select the most capable appropriate Windows UI, statistical engine, database, Python/ML ecosystem, query system and visualization stack on engineering merit. Focus on functioning software rather than prolonged planning or elaborate documents.

Read PROJECT_VISION.md fully. Make normal implementation decisions autonomously. Explore ambitious capabilities beyond the examples when justified by data and tests. No artificial cap on selected metrics, comparison dimensions, or experimental models; implement resource-aware execution.

## Research-first data policy
This is private, noncommercial research. Do not impose speculative commercial app-store or redistribution constraints on permissible personal experiments. Claude's existing safeguards apply. Respect applicable laws, binding agreements, credentials, and explicit access restrictions. When commercial suitability is uncertain but private research is permitted, experiment and record the issue in PUBLIC_RELEASE_REVIEW.md rather than stopping. Where a concrete restriction affects the research itself, find a lawful permitted alternative. Never purchase paid feeds or services without owner approval. Keep API keys out of source control.

## Execution
- Inspect this new repository and implement immediately; avoid generating a conventional app template.
- Establish a working Windows-first development environment and choose a maintainable, testable stack. A Python analytical backend and desktop/webview shell are acceptable if justified.
- Build a usable end-to-end slice quickly; iterate on real functionality.
- Prefer real, permitted data; otherwise clearly labeled synthetic demonstrations. Never present demo projections as real picks.
- Implement the natural-language Query Inspector and underlying deterministic calculation engine, not just a chatbot.
- Build online-first provider adapters and event-triggered projection refresh, with freshness/conflict indicators.
- Add reproducible tests for formulas, missing data, minute totals, injury scenarios, source timestamps, and leakage.
- Use GitHub as source of truth. Create a development branch after initial repository setup, keep main protected by owner approval, and do not publish publicly.
- Verify a Windows build using an actual Windows environment/runner; a Linux test is not proof that a Windows installer works.
- Keep short, useful technical notes and a candid status report. Document genuinely reusable modules and public-release concerns.

## Initial deliverable
A launchable Windows application and installation instructions; searchable stats and players/teams; customizable analytical workbench; structured natural-language query with inspectable calculations and games; basic projections and fantasy rankings; source-status monitor; model evaluation dashboard; verified tests/builds; known gaps; recommended next experiments.

Do not stop after a plan. Fix routine errors and continue. Ask approval only for purchases, access requiring owner action, main merges, public releases, or major changes outside the approved research scope.
